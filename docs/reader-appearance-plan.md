# Sepia reader page color — implementation plan

**Scope.** Add one warm, light preset to **Reader Settings → Page Color** for HTML, EPUB, TXT, and Markdown. Use a labeled 2×2 radio group in reading order: **Default, Sepia** on the first row and **Gray, Black** on the second. Selecting Default resumes following the app theme. This is the way back from Sepia; the picker needs no reset action. Apply changes immediately to the open page.

1. **Extend the existing preference (complete).** Add `sepia` to `READER_PAGE_THEMES` in `src/components/ReaderSettings/useReaderSettings.ts`. Use the existing settings key, normalizer, and cross-book persistence. In `useReaderSettings.test.ts`, turn the current invalid-Sepia example into an acceptance case and keep an unknown-value fallback case. Check that existing saved choices reopen correctly and a missing preference still selects Default.
   - Verified all four choices round-trip through the settings panel, local storage, and a fresh mount. Missing and unknown values resolve to Default. The picker already renders the typed theme list, so stage 1 includes the Sepia label in all eight locales.
2. **Update the picker (complete).** The four labeled swatches use a two-column grid, a visible native radio dot for selection, and an outline around the keyboard-focused label. The settings popover's single grid track can shrink to its available width, so enlarged labels wrap within the panel.
   - Chromium regression: at a 320 CSS pixel viewport with Arabic RTL and a 24px root font, all four options fit in the panel in right-to-left reading order. Arrow Down selects Sepia from Default. Tab leaves the group and removes its focus outline while Sepia stays checked.
3. **Apply the palette to the reader surface (complete).** The reflowable reader uses ivory paper (`#F5EBD7`), brown ink (`#392F25`), muted text (`#685744`), and blue links (`#245674`). Reader tokens also cover headings, hover, quotes, table and code surfaces, borders, and Find highlights. Images retain their colors because the palette styles text and surfaces directly.
   - The Chromium picker regression selects Sepia in a dark app and checks the rendered paper and ink colors, the page's light color scheme, and the toolbar's dark color scheme.
4. **Verify contrast where text is actually drawn (complete).** A Chromium regression measures contrast from computed styles on the mounted Sepia article in both Light and Dark. It covers body text, links, quotes, captions, code blocks, table headers, restored HTML colors, ordinary and current Find matches, search destinations, and registered read-aloud sentence and word ranges.
   - On caption ink, the translucent word highlight layered over the sentence measured 3.93:1 in Light and 3.73:1 in Dark. Sepia now uses opaque pink sentence and word fills. With caption ink these give 5.50:1 and 4.81:1 respectively. The fixture checks a minimum of 4.5:1 for every tested text pair.
   - Legacy `color` and `bgcolor` attributes in restored books now defer to the Sepia palette in either app theme.
5. **Acceptance (complete).** The Chromium regression selects Sepia through Reader Settings, opens generated EPUB, TXT, and Markdown reading HTML, switches to a PDF.js page, and returns to another HTML document. It checks the illustrated EPUB, the absence of reflowable theme controls on PDF, and that selecting Default restores the dark app's page color. The settings tests separately check preference persistence across fresh mounts. See the [viewer architecture summary](user-document-search.md#frontend-and-viewer-architecture) for the supported page colors.
