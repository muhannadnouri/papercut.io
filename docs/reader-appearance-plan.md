# Sepia reader page color — implementation plan for review

**Scope.** Add one warm, light preset to **Reader Settings → Page Color** for HTML, EPUB, TXT, and Markdown. Use a labeled 2×2 radio group in reading order: **Default, Sepia** on the first row and **Gray, Black** on the second. Selecting Default resumes following the app theme. This is the way back from Sepia; the picker needs no reset action. Apply changes immediately to the open page.

1. **Extend the existing preference.** Add `sepia` to `READER_PAGE_THEMES` in `src/components/ReaderSettings/useReaderSettings.ts`. Use the existing settings key, normalizer, and cross-book persistence. In `useReaderSettings.test.ts`, turn the current invalid-Sepia example into an acceptance case and keep an unknown-value fallback case. Check that existing saved choices reopen correctly and a missing preference still selects Default.
2. **Update the picker.** In `ReaderSettings.tsx` and `ReaderSettings.css`, reuse the fieldset, visible labels, and native radios. Switch the grid to two equal columns, add the Sepia swatch, and show selection with a visible radio dot or check as well as color. Keep keyboard focus distinguishable from selection. Translate the label in all eight locale files. Verify click and arrow-key selection, checked state, and label wrapping at a narrow width with enlarged UI text and Arabic RTL.
3. **Apply the palette to the reader surface.** Extend the existing `data-reader-theme` rules in `DocumentViewer.css` and give the Sepia document surface a light CSS color scheme even inside a dark app. Start with paper `#F5EBD7`, ink `#392F25`, muted text `#685744`, and links `#245674`. Complete the reader tokens for headings, links on hover, subtle surfaces, borders, and highlights. Use surface and text colors directly so images retain their authored colors. Keep the existing non-PDF viewer boundary.
4. **Verify contrast where text is actually drawn.** Check ordinary text at 4.5:1 or better on paper, table headers, code blocks, and highlighted passages. Exercise links, captions, quotes, legacy HTML with `color` or `bgcolor`, ordinary and current Find matches, and a search-result destination. Read-aloud sentence and word highlights in `src/tts/alignment/highlightRanges.ts` use separate app-level variables. Test both against Sepia ink with the app in Light and Dark and scope any needed override to the reader. Cover the dark-app/light-page combination in a browser regression.
5. **Run acceptance checks and document the result.** Run the focused settings and browser tests, locale validation, type checking, and the frontend build. On desktop and a narrow mobile reader, switch between Sepia and Default in an open book, then reopen the app and switch books to check persistence. Exercise an illustrated EPUB and HTML with Find and read-aloud, spot-check TXT and Markdown, and open a PDF to verify its usual controls and page rendering. Confirm the toolbar follows the app theme throughout. Update the [viewer architecture summary](user-document-search.md#frontend-and-viewer-architecture) after verification.
