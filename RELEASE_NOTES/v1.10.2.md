# Papercut v1.10.2 - Release Notes

- **Target release:** 1.10.1
- **Release type:** Cross-platform patch release: audiobook playback and reader
  bookmark fixes, an Erase All Data action, security dependency updates, and the
  first production-signed Android build

## TL;DR

Papercut v1.10.2 makes saved audiobooks playable from almost anywhere in a long
book, makes bookmark restoration dependable, lets file managers open exported
`.papercut-audiobook` bundles directly, and adds **Erase All Data** to Settings.
It also picks up security updates for the archives Papercut imports, and is the
first Android release signed with the production Papercut key on the road to
F-Droid.

The practical highlights are:

- Play-anywhere and play-from-here recover per chapter instead of reporting
  "Audio could not be matched" for the rest of a long audiobook.
- Playback now starts proportionally inside the narrated chunk, closing most of
  the gap between the passage on screen and the audio you hear.
- Bookmark restoration shows your place while it restores, retries failed
  seeks, and no longer jumps to the top of the document.
- Exported `.papercut-audiobook` bundles open directly via your file manager's
  open-with on Android and desktop.
- **Erase All Data** in Settings removes everything Papercut stores on the
  device after an explicit, itemized confirmation.
- Security updates to `pulldown-cmark`, `zip` and `serde_with`, with strict ZIP
  header validation before any archive content is read.
- Android APKs are now signed with the production key and reproducibly build
  from source.

## Added

### Erase All Data (Android, iOS, desktop)

- Settings → Reset App Data → **Review Data to Erase** shows every category
  Papercut will remove, with counts and total size, before you confirm with
  **Erase Everything**. The action removes documents, bookmarks, audiobooks,
  transfer records, downloaded models and preferences, and returns the app to
  its starting state.
- The erase cannot be undone and is not a secure overwrite: files are deleted
  through the filesystem. On desktop the confirmation also shows the app data
  and cache folders, and reminds you that a library export is not a full
  backup.
- Audio playback keeps running until the wipe succeeds, so a refused or failed
  erase never interrupts what you are listening to.

### Audiobook bundles via open-with

- Tapping an exported `.papercut-audiobook` bundle in a file manager previously
  offered no app to open it. The bundle type is now registered with Android
  intent-filters and desktop installers, so shared audiobooks open directly
  through open-with and import like any document.

### Play-anywhere proportional start

- Saved audiobooks carry chunk-level timing, so playback used to start at the
  boundary of the narrated chunk — typically a few seconds above the passage on
  screen. Play-anywhere now starts proportionally inside the containing chunk,
  audibly closer to where you stopped reading.

## Fixed

### Audiobook playback

- One chapter with a damaged or unverifiable position no longer disables
  play-from-here for the whole book. Affected chunks drop out of matching
  alone; healthy chapters keep their saved positions, and damaged ones recover
  from the document text when possible instead of reporting "Audio could not be
  matched".
- Explicit play starts always reveal and follow the passage they began from,
  capture respects the reading focus band, and proportional seeking is scoped
  to real playback commands so it can no longer drift during recovery.

### Reader bookmarks

- Bookmark restoration keeps your current page visible until the destination
  is ready, renders a restoring indicator, retries cancelled or failed seeks,
  and no longer lands at the top of the document. Restoration now survives
  viewer lifecycle changes, and stale caches are invalidated when the viewer
  is disposed.

### Import

- Batches of files opened from other apps (open-with) are no longer dropped
  when the library is busy importing; drained sources are preserved and
  imports run serially.
- Audiobook import failures now surface as visible notices in Library, Search,
  Audiobooks and the reader instead of failing silently.

## Security

- `pulldown-cmark` updated to 0.13.6 (RUSTSEC-2026-0414, RUSTSEC-2026-0433).
- `zip` updated to 9.0.5 with header-consistency validation enabled before
  library or EPUB archive content is read, on top of the existing bounded
  preflight, duplicate-entry checks, canonical paths and payload checksums.
  Malformed-header, duplicate-name and overlap regressions are covered by
  tests.
- `serde_with` updated to 3.22.0.

## Android

- Release APKs are now signed with the production Papercut signing key. This
  key is the update identity for the website, GitHub releases, and the planned
  F-Droid distribution.
- The Android build is designed to be reproducible from source: the F-Droid
  buildserver recipe already reproduced an earlier Papercut build
  byte-for-byte in an independent verification run, the same proof is
  repeated for every release before publication, and third-party license
  notices are bundled and verified in every APK.
- **Upgrade note for sideload users:** Android refuses updates that change the
  signing key. Earlier website releases were debug builds signed with an
  automatically generated debug key, so if you installed Papercut from the
  website before v1.10.2, uninstall it and install this release fresh.
  Before uninstalling, move your library off the device — a direct Library
  Transfer to another device or a library export — following the steps in
  [docs/library-transfer.md](docs/library-transfer.md). Both paths carry
  documents (and audiobooks when you include them), but not bookmarks or
  reading preferences, which cannot be restored from either. Fresh installs
  are unaffected.

Existing libraries, transfers and audiobooks remain fully compatible with
v1.10.0.
