# Papercut v1.9.0 - Release Notes

- **Target release:** 1.9.0
- **Release type:** Cross-platform minor feature release
- **Release status:** Release candidate preparation

## TL;DR

Papercut v1.9.0 turns the PDF foundation introduced in v1.8.0 into a local
scanning and recognition workflow. Image-only and hybrid PDFs can now be
recognized on demand in English or Arabic, searched, selected, narrated, and
revisited without changing the original PDF. Supported Android devices can
also scan multi-page documents or import existing photos into the same offline
PDF pipeline.

This release also adds document-scope search, recursive desktop folder imports,
PDF fullscreen reading, more explicit bookmarks, low-glare reader themes,
guided voice-model installation, recommended voice previews, legal/notices
screens, and a generated public website in eight languages. It includes broad
mobile, accessibility, lifecycle, and security hardening.

The practical highlights are:

- Recognize image-only and hybrid PDF pages locally in English or Arabic.
- Search, Find, select, highlight, and narrate recognized PDF text.
- Resume interrupted recognition without exposing partial results.
- Scan, crop, reorder, and recover multi-page documents on supported Android
  devices, or import existing mobile photos.
- Include or exclude selected documents before Library search result limits.
- Preserve up to five visible folder levels during recursive desktop imports.
- Import plain-text and CommonMark Markdown files—or paste plain text directly—
  into the same searchable, readable, and listenable local Library.
- Preview the recommended voice before starting an audiobook.
- Use fullscreen PDF reading and persisted Gray or Black HTML/EPUB page themes.
- Read the Papercut license, AI audio notice, and third-party notices in-app.

Papercut v1.9.0 remains compatible with existing `1.x` libraries and portable
formats. The release adds derived recognition data and additive metadata; it
does not intentionally rewrite canonical documents or require a library reset.

## Added

### Offline English and Arabic PDF recognition

- **Recognition readiness.** Imported PDFs are classified as ready,
  recognition-required, or recognition-available without blocking searchable
  hybrid documents that already contain useful native text.
- **Bundled on-device OCR.** Papercut packages Tesseract.js 7, its local worker
  and WASM cores, and pinned English and Arabic trained data. Recognition does
  not require a CDN, cloud account, or document upload.
- **Explicit language choice.** Users choose English or Arabic before
  recognition. Papercut does not silently guess between languages, and retries
  retain the chosen language.
- **Image-only PDF support.** Fully textless PDFs can be recognized page by page
  and finalized into the existing local PDF text and search architecture.
- **Selective hybrid recognition.** Papercut recognizes only image-backed pages
  with missing or weak native text while preserving native and intentionally
  blank pages.
- **Searchable derived text.** Recognized pages participate in Library search,
  exact-result navigation, in-document Find, selection, highlighting, and TTS.
- **Selectable overlays.** Transparent, line-fitted text overlays map persisted
  OCR words back onto the original page without painting replacement glyphs
  over the scan.
- **Reader-centered workflow.** A contextual reader control explains when text
  recognition is required or optionally available instead of repeating the
  same action across every Library surface.
- **Bounded recognition.** One reusable worker processes one bounded page render
  at a time. Ordinary pages render at 300 DPI while unusually large pages are
  capped at a nine-megapixel canvas.
- **Progress and cancellation.** Preparing, page recognition, indexing,
  stopping, review, and failure states are visible in the reader and Library.
- **Durable resume.** Minimal recovery metadata and atomically written page
  sidecars allow interrupted work to continue after an app restart without
  restarting completed pages.
- **Targeted retry.** Failed and low-confidence pages can be retried without
  discarding successful pages. The optional improvement pass keeps the existing
  result unless the replacement maintains or improves usable text quality.
- **Review and acceptance.** Completed jobs distinguish successful, partial,
  and review-required outcomes and let users accept usable derived text while
  retaining the original PDF.

### Mobile document scanning and photo import

- **Android document camera.** A local CameraX workflow captures one or many
  pages without depending on Google Play Services.
- **Manual page correction.** Android users can adjust four crop corners,
  rotate or retake a page, and review the corrected result before accepting it.
- **Page management.** Accepted pages have file-backed thumbnails and can be
  selected, reordered, or deleted before final PDF creation.
- **Bounded thumbnail memory.** The Android thumbnail strip uses RecyclerView so
  only visible and recycled thumbnail bitmaps remain in memory.
- **Interruption recovery.** Accepted Android pages survive Activity recreation,
  transient camera or assembly failures, and full app restarts.
- **Continue or start over.** A later scanner launch can continue the newest
  complete Android draft or explicitly discard it and start a new scan.
- **Storage preflight.** Camera and photo workflows check available storage
  before capture and final PDF assembly while preserving recoverable pages when
  a transient operation fails.
- **Existing-photo import.** Android's system document picker and iOS PhotosUI
  can select existing images without broad photo-library permissions.
- **Shared processing path.** Camera and photo output is normalized into an
  app-owned canonical PDF and then uses the existing importer, OCR, indexing,
  viewer, search, and narration pipeline.
- **Scan setup.** A localized dialog collects the display title and English,
  Arabic, or unsupported-language choice before native capture or photo import.
- **Native output limits.** Camera and photo output is limited to 500 pages and
  250 MB, then independently revalidated at the Rust boundary.
- **iOS implementation.** VisionKit document capture, PhotosUI import, bounded
  PDF assembly, and camera permission declarations are implemented. The iOS
  scanner must not be advertised as validated until physical-device acceptance
  is complete.

### Library and search

- **Include and exclude search scopes.** Filter By Document can search only
  selected documents or exclude them. Scope resolution is shared by Pagefind
  and uploaded-document SQLite search and is applied before provider limits.
- **Recursive desktop folder import.** Desktop imports preserve supported files
  through five visible folder levels, skip symlinks and deeper content, and
  reproduce the folder structure atomically in Library metadata.
- **Plain-text and Markdown import.** File and desktop-folder imports accept
  `.txt`, `.md`, and `.markdown` alongside HTML, EPUB, and PDF. Plain text is
  escaped into reflowable paragraphs; CommonMark structure is rendered and
  passed through the existing HTML sanitizer before local indexing and TTS.
- **Paste Text.** Create a titled, searchable plain-text Library document from
  the Import menu without granting clipboard access or creating a temporary
  file. Failed saves keep the entered text available for retry.
- **Strict text decoding.** TXT and Markdown accept UTF-8 and BOM-marked UTF-16
  without guessing ambiguous legacy code pages. Identical bytes imported as
  plain text and Markdown retain separate identities because they render with
  different semantics.
- **Folder collision handling.** A conflicting imported top-level folder gets a
  unique suffix instead of merging into an existing Library tree.
- **Clear duplicate results.** Import summaries distinguish newly added,
  already-present, and failed files and expose reusable or failed filenames in
  accessible expandable lists.
- **Better filtered trees.** Document filtering expands matching folder paths,
  hides empty branches, and restores the full hierarchy and expansion state
  when the filter clears.
- **Improved Library management.** Management controls remain visible while
  scrolling, User Uploads are prioritized in gallery ordering, and folder
  selection, blocked deletion, and metadata actions have clearer states.

### Reader and PDF controls

- **PDF fullscreen mode.** The PDF toolbar can enter and exit native fullscreen
  where available, with a mobile WebView fallback and synchronized Escape or
  native fullscreen exits.
- **Responsive PDF toolbar.** Page navigation and zoom remain directly
  available on narrow screens while secondary layout, spread, outline, and
  fullscreen actions move into one accessible overflow menu.
- **Fullscreen menu access.** The PDF More Actions popover renders inside the
  fullscreen reader portal so Android and desktop WebViews do not hide it.
- **Explicit bookmarks.** Existing bookmarks offer Return, Move, and Remove
  actions instead of being silently overwritten or removed.
- **Bookmark undo.** Moving or removing a bookmark provides a short-lived undo
  action.
- **Reader page themes.** HTML and EPUB readers add persisted Default, Gray, and
  Black page appearances. PDF pages retain their authored colors.
- **Low-glare styling.** Gray and Black appearances use semantic colors for
  prose, headings, links, tables, code, selection, and separators without
  rewriting imported content.

### Audiobook setup and voice previews

- **Missing-model guidance.** Reader audiobook actions distinguish an
  uninstalled voice model from an unavailable SILMA runtime and open the shared
  Audio Setup dialog at the corrective action.
- **Recommended voices.** Each model's existing default voice is identified as
  the recommended starting point; no separate ranking system is introduced.
- **Localized voice samples.** Audio Setup provides language-matched sample text
  for every supported voice language.
- **Temporary native previews.** Preview reuses the installed model,
  preprocessing, and native synthesis path without creating audiobook records
  or retaining preview audio.
- **Clear Preview/Stop states.** The preview action displays a play icon at rest,
  the existing spinner during synthesis, and a stop icon during playback, with
  matching live and pressed-state feedback.
- **Playback coordination.** Starting a preview stops current audiobook
  playback, prevents overlapping previews, fences stale requests after model or
  voice changes, and removes temporary audio on completion.

### Settings, legal information, and public website

- **Legal & Notices.** App Settings now presents Papercut's MIT license, the AI
  audio use notice, and third-party notices in a responsive list/detail view.
- **Safe notice links.** Legal content uses readable formatting, safe external
  links, keyboard navigation, RTL layout support, and consistent back actions.
- **Third-party disclosures.** Notices include the retained PDF.js viewer asset
  covered by MPL-2.0 and the applicable bundled dependency licenses.
- **Eight-language website.** The public site is available in English, Arabic,
  Spanish, French, Italian, Brazilian Portuguese, Hindi, and Simplified Chinese.
- **Generated locale pages.** One dependency-free Node generator combines a
  shared template with strict per-locale catalogs and rejects missing or unused
  translation values.
- **Self-hosted multilingual font.** The website packages the licensed Readex
  Pro font locally for consistent Latin, Arabic, and Devanagari presentation.
- **Deployment generation.** Netlify regenerates localized pages before
  publishing while committed output remains available for direct previews.
- **RTL website support.** Arabic metadata, navigation, layout, forms, theme
  controls, canonical URLs, and reciprocal `hreflang` links use the shared
  logical-property layout.
- **Accurate public claims.** README, release messaging, and website copy now
  describe English/Arabic OCR and Android scanning with explicit iOS and desktop
  boundaries. The existing Demo section remains reserved for future screenshots
  and English/Arabic voice samples.

## Changed

### PDF recognition architecture and behavior

- The original PDF remains canonical. Recognition writes rebuildable page-text
  sidecars and search rows rather than altering source bytes.
- Searchable hybrid PDFs remain immediately usable even when some image-backed
  pages can optionally be improved with OCR.
- Required recognition, optional improvement, active work, review, and error
  states use one shared lifecycle instead of separate scanner and reader jobs.
- PDF Find selects its indexed OCR path before virtualized pages render and
  disposes native PDF.js listeners when changing search implementations.
- Search-target navigation uses bounded fallback timers when PDF.js does not
  emit a terminal text-layer event.
- Page sidecars are written through same-directory temporary files and promoted
  atomically so incomplete JSON cannot become finalized derived data.

### Import, organization, and presentation

- Desktop folder imports changed from one level to recursive traversal through
  five visible folder levels.
- Android builds no longer compile or expose desktop-only folder import helpers.
- Gallery/list filtering and folder browsing now keep contextual management
  actions visible and remove empty filtered branches.
- Document delete actions use the shared tonal danger treatment in light and
  dark themes.
- English interface labels received a consistent title-case pass.
- HTML/EPUB reader outlines now preserve border geometry without using a
  contrasting outer stroke under tonal page themes.
- Reader font menus use the interface font for stable, responsive option
  rendering while the selected typeface remains applied to document content.
- Applying a reader font keeps the document visible and reports its status
  before large HTML or EPUB layouts are reflowed.
- EPUB illustrations now remain separate from generated reading HTML and load
  lazily in the same continuous page, reducing initial parsing and decoding work
  for image-heavy books. Supported referenced raster images—including those in
  image-only spine sections—are preserved across library transfer, while older
  inline-image imports continue to open and upgrade locally when possible.
- Long document imports now report localized stages such as reading, preparing,
  saving, and PDF text extraction without presenting misleading percentages.
  Document opening progressively adds preparation detail and a large-file
  reassurance only when the wait is long enough to need explanation.

### Build and dependency requirements

- PDF asset preparation now stages PDF.js rendering assets and local Tesseract
  worker, core, and language files through one `prepare:pdf-assets` command.
- PDF.js was upgraded from 6.1.200 to 6.2.108.
- Vite was upgraded from 7.3.1 to 7.3.5.
- The documented Node.js minimum is now 22.13.0, matching PDF.js requirements.
- The declared Rust minimum is now 1.88, matching the committed dependency
  graph.
- CI watches the local document-scanner plugin when deciding which native jobs
  to run.

## Fixed

### OCR, search, and data integrity

- Hybrid PDFs no longer route recognized pages through only the native PDF.js
  text layer when weak embedded text is still present.
- Native and OCR text are not duplicated when finalizing hybrid documents.
- OCR Find can highlight indexed matches across native and recognized page
  layers without exposing approximate replacement glyphs.
- OCR selection groups and measures complete lines to avoid overlapping word
  glyphs and unusable native selection handles.
- Arabic OCR selection and search use normalized text while preserving page
  coordinates and source-to-glyph mapping.
- A recognition retry that returns partial results no longer reports a complete
  job as a generic failure or discards previously useful text.
- Hybrid recognition that adds no characters still preserves usable native
  text and resolves document readiness correctly.
- Accepted recognition clears stale recovery intent so completed work is not
  offered again after restart.
- Persisted recovery metadata validates app-owned document URLs, page indices,
  targeted-page counts, and document page limits before resuming.
- Oversized recovery arrays are rejected before scanning their entries.
- PDF source and sidecar loading failures now produce normalized document errors
  instead of leaking parser-specific failures.

### Scanner reliability and resource handling

- Android crop corners retain their normalized positions through review layout
  changes.
- Scanner worker results update UI only while the Activity remains live; stale
  results recycle bitmaps and remove uncommitted page files.
- Android accepted pages survive Activity recreation, low storage, capture
  failures, preview failures, page-write failures, and PDF assembly failures.
- Android photo import opens the system picker without an unreliable package
  visibility preflight.
- Native scanner paths are canonicalized before validating that completed output
  belongs to app-owned staging.
- Completed scanner staging is removed after canonical import while separate
  resumable Android drafts remain available.
- Scanner cleanup is idempotent and removes abandoned completed staging before
  later capture attempts.
- File-level batch import errors remain visible when automatic recognition of a
  newly scanned PDF also runs.
- VisionKit PDF assembly runs off the iOS main thread so large reviewed scans do
  not freeze the WebView during finalization.
- Android scanner and photo import share one overflow-safe free-space preflight.

### Reader, Library, and accessibility

- Compact PDF controls no longer clip or leave secondary view actions
  unreachable on narrow mobile screens.
- Two-page spread remains selectable from compact view menus.
- The fullscreen PDF action menu remains visible and interactive inside native
  fullscreen WebViews.
- Fullscreen toolbar focus handling no longer relies on unsupported
  `:focus-visible` DOM queries.
- Compact PDF view options expose their selected state to assistive technology.
- OCR running, review, and error changes use atomic live announcements,
  accessible busy labels, wrapped issue lists, and larger coarse-pointer targets.
- Native Android scanner progress is exposed through an accessibility live
  region, and crop adjustment is described as optional rather than mandatory.
- Library duplicate imports no longer appear as generic failures.
- Filtered folder trees no longer show empty folders or an empty User Uploads
  section.
- Blocked folder-delete, metadata edit, and document-delete controls have
  consistent visual and accessible states.

### Text-to-speech

- British Kokoro voices now use eSpeak's supported `en` locale instead of the
  unsupported `en-gb` value that could abort the native process.
- Mandarin Kokoro synthesis remains in sherpa's Chinese/English lexicon mode,
  preventing native preview and audiobook crashes for mixed Chinese and Latin
  text.
- Missing voice models and missing SILMA runtime setup now lead to the correct
  actionable Audio Setup state.
- Completed audiobooks can still open Audio Setup when their recorded model or
  runtime is unavailable.
- Preview errors and stale synthesis requests cannot unexpectedly begin playback
  after the selected model or voice changes.

### Security and dependency maintenance

- PDF.js 6.2.108 addresses arbitrary JavaScript execution when opening a
  malicious PDF.
- Vite 7.3.5 resolves reported development-server vulnerabilities.
- Native scanner output is independently constrained and path-validated at both
  the plugin and Rust IPC boundaries.
- OCR recovery data accepts only bounded, app-owned PDF work rather than trusting
  persisted browser storage.

## Compatibility And Upgrade Notes

- Existing HTML, EPUB, and PDF documents remain supported; TXT and Markdown are
  additive import formats and do not change existing source identities.
- Existing saved audiobooks and `.papercut-audiobook` bundles remain supported.
- Existing `.papercut-library` transfer packages remain supported; this release
  does not add reading progress, bookmarks, or preferences to transfer files.
- Existing PDF sources are not rewritten. Recognition creates derived sidecars
  and search data that can be rebuilt or removed independently.
- Existing finalized textless PDFs are backfilled with recognition readiness
  when the local upload store opens; users do not need to re-import them.
- Existing searchable hybrid PDFs stay searchable before optional recognition.
- OCR language, retry targets, and interrupted-job state are local recovery data
  and do not change audiobook or portable-library format versions.
- Reader Gray and Black themes affect presentation only and do not alter stored
  HTML/EPUB content or saved audiobook metadata.
- The Linux x64 SILMA runtime continues using its immutable verified v1.8.0
  runtime-pack assets. The application version bump does not rename or republish
  those checked runtime files.

## Known Limitations And Release Gates

- OCR includes English and Arabic only. Automatic language detection and
  additional trained-data packages are not included.
- Arabic OCR is implemented, but physical-device accuracy and performance
  validation remain open and must not be inferred from English acceptance.
- Android scanning and photo import have passed physical-device workflow,
  interruption, restart, and low-storage acceptance on the tested device set.
- iOS VisionKit scanning and PhotosUI import are implemented and buildable, but
  physical-device acceptance remains open; they are not yet a validated public
  capability.
- Desktop builds can import PDFs but do not expose webcam scanning or direct
  image-to-PDF import.
- Android uses a manual four-corner correction flow; automatic page-edge
  detection is intentionally deferred until real use demonstrates a need.
- Recognition can resume after interruption, but it is not a native background
  service and does not continue processing after the WebView/app is stopped.
- Active scans are capped at 500 pages and 250 MB of native output.
- OCR quality depends on source resolution, contrast, layout, typography, and
  language. Review remains appropriate for low-confidence or complex pages.
- Voice preview requires the selected model/runtime to be installed first.

## Release Verification

Before tagging `v1.9.0`:

- Run `npm run lint`, `npm test`, `npm run build`, and `npm run check:i18n`.
- Run the Rust library suite and native-TTS feature suite.
- Run the generated PDF boundary-fixture checks and confirm packaged OCR assets
  make no CDN requests.
- Build desktop installers and smoke test one installed artifact outside the dev
  server on Linux, Windows, and macOS.
- Verify PDF.js 6.2.108 rendering, text extraction, Find, search navigation,
  fullscreen, bookmarks, and TTS on representative PDFs.
- Recognize English and Arabic image-only and hybrid PDFs; verify cancellation,
  restart resume, targeted retry, source preservation, Find, Library search,
  selection, highlights, and ordered TTS.
- On Android, scan and import photos for a multi-page document; verify crop,
  rotate, retake, reorder, delete, interruption, restart, low-storage recovery,
  OCR handoff, and cleanup.
- Complete iOS physical-device scanner/photo-import acceptance and record the
  result before advertising iOS scanning as supported.
- Test include/exclude search scopes against bundled and uploaded documents,
  including an empty active scope and stale in-flight searches.
- Test recursive folder import, duplicate reporting, filtered nested folders,
  and Android's absence of desktop folder controls.
- Test PDF fullscreen and compact controls with keyboard, touch, 200% zoom, and
  screen-reader navigation.
- Preview representative voices for every catalog language and verify British
  English and mixed Mandarin/Latin synthesis in both preview and audiobook paths.
- Verify every Legal & Notices document and external link in LTR and RTL layouts.
- Regenerate all website locales and validate templates, internal anchors,
  canonical URLs, `hreflang`, and v1.9.0 asset names.
- Build and sign release artifacts through the tag workflow, verify generated
  SHA-256 sums, and test each published download link before deploying the
  updated website.
